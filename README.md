# 에이텍그룹 공정거래 CP 데스크

계열사 구성원이 공정거래 자율준수프로그램(CP)의 도입 진척을 보고, 매월 본인 자가진단을 제출하는 초기 운영 화면입니다.

## 화면

- 도입 현황: 내부 실행 달성률, 2027년·2030년 목표, 네 개 운영 축, 계열사 제출률, 등급 경로
- 실행 과제: 매뉴얼 8대 요건과 과제별 달성률, 과제 상세
- 본인 자가진단: 로그인한 계정의 객관식 50문항, 주관식 5문항, 불만 사항, 개선 사항. 입력완료 시 담당자에게 메일을 보냅니다.
- 감사팀: 승인된 감사팀 관리자만 제출 원문, 실행 진척, 문항, 계열사 대상 인원, 직원 승인을 다룹니다.

달성률은 감사팀이 관리하는 내부 진척입니다. 공정위 등급평가 점수와 같지 않습니다. 현재 등급은 없고, 2028년 최초 평가 목표는 A, 2030년 목표는 AA입니다.

## 내 컴퓨터에서 실행

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:4317 을 엽니다. 이 주소는 그 컴퓨터에서 서버가 켜져 있는 동안만 열립니다.

화면을 끈 뒤에도 같은 주소로 다시 보려면, 프로젝트 폴더에서 `npm run dev`를 다시 실행합니다.

## 깃허브에서 관리

코드의 기준은 [asiaraya62-lang/ateccp](https://github.com/asiaraya62-lang/ateccp)의 `main` 브랜치입니다. `main`에 올리면 `.github/workflows/ci.yml`이 설치와 빌드를 검사합니다. 제출 원문(`data/submissions.json`)과 `.env.local`은 저장소에 올리지 않습니다. 비밀번호는 이 문서에 적지 않습니다.

## 깃허브 저장소로 항상 열리게 배포

이 화면은 로그인과 데이터 API가 있는 서버입니다. `github.io` 페이지는 파일을 보여주는 주소라서 그 서버가 켜지지 않습니다. 같은 깃허브 저장소의 `main`을 서버 호스트에 한 번 연결하면, 이후 `main`에 올릴 때마다 같은 주소로 다시 배포됩니다.

1. [이 저장소를 배포](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fasiaraya62-lang%2Fateccp&project-name=ateccp) 페이지를 엽니다. 깃허브 계정 `asiaraya62-lang`으로 로그인합니다.
2. `CP_SESSION_SECRET`에 긴 임의 값을 넣습니다. HTTPS에서는 `CP_COOKIE_SECURE=true`로 둡니다. 메일을 쓸 때는 `CP_MAIL_TO`, `CP_MAIL_FROM`, SMTP 또는 `RESEND_API_KEY`를 넣습니다.
3. Deploy를 누릅니다. 주소는 `https://….vercel.app` 형태로 유지됩니다.

그 주소의 디스크에는 직원 신청, 승인, 진척 수정, 제출 원문이 남지 않습니다. 메일이 연결되기 전에는 입력완료가 저장되지 않고, 연결이 필요하다는 안내가 나옵니다. 실행 과제와 문항의 기본값은 저장소에 포함된 파일입니다. 제출과 직원 명단을 파일로 계속 쌓으려면 내 컴퓨터에서 `npm run dev`로 실행하세요.

## 메일

`.env.example`을 `.env.local`로 복사한 뒤 담당자 주소를 넣습니다.

- `CP_MAIL_TO`: 감사팀 담당자
- `CP_MAIL_FROM`: 발신 주소
- SMTP(`SMTP_HOST` 등) 또는 `RESEND_API_KEY` 중 하나

내 컴퓨터에서 메일 서버가 없으면 제출은 저장되고 감사팀 수신함에 남습니다. 발송되지 않은 상태로 표시됩니다. 배포된 주소에서는 파일을 남길 수 없어서, 메일이 없으면 제출이 받아들여지지 않습니다.

## 로그인

로그인하지 않으면 어떤 화면이든 로그인 페이지로 이동합니다. 로그인에 성공하면 도입 현황이 열립니다.

초기 감사팀 관리자 사번은 `AUDIT`입니다. 비밀번호는 저장소 밖에 따로 전달합니다. 실제 운영 전에 그 비밀번호와 `CP_SESSION_SECRET`을 바꾸세요. 예전 공유 접근 코드 화면은 없습니다.

일반 직원은 로그인 화면의 접속 신청으로 계정을 만듭니다. 승인 전에는 들어갈 수 없고, 감사팀 관리자가 직원 탭에서 승인한 뒤에 로그인합니다. 승인한 직원은 도입 현황과 실행 과제를 보고, 자가진단은 본인 기록만 작성·조회합니다. `/audit`와 `/api/audit`는 승인된 감사팀 관리자만 엽니다.

## 데이터

- `data/plans.json`: 실행 과제와 달성률, 목표
- `data/questions.json`: 자가진단 문항. 감사팀 화면에서도 고칠 수 있습니다.
- `data/companies.json`: 계열사와 참여 대상 인원
- `data/users.json`: 직원 계정. 비밀번호는 해시만 저장합니다.
- `data/submissions.json`: 제출 원문. 저장소에는 올리지 않습니다.

대상 인원은 공시 직원 수가 아니라 감사팀이 정하는 참여 기준입니다.

내 컴퓨터에서 실행하면 제출 원문은 `data/submissions.json`에 쌓입니다. 이 파일은 저장소에 올리지 않습니다.
